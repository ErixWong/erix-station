## 0. 一句话

> **它是一个「事件 → 事实 → 规则 → 判决」的平台：把世界里发生的事拉平成一张可查询的影子表，
> 在表上写「什么状态算需要行动」，让带契约的执行者去行动，并**用独立于执行者的判据**验收它到底算不算数。**

产物不是「一次触发」，也不是「一个应用」，而是**一条被带证据关闭的工作项**。

## 1. 为什么单独一个目录

三条理由，都不是「文件太多」：

1. **它不是 station 的规格。** station 的规格回答「一个 run 怎么安全地发生」；本目录回答
   「这个 run 该不该发生、发生完算不算数」。混进 `fde-platform.md` 会让两份文档互相污染——
   而 station 马上要做大升级，污染代价会翻倍。
2. **它跨产品。** 同一套模型既要能服务 station（开发工位），也要能服务一个独立产品（数字员工）。
   写进 station 的规格就等于把产品边界写死在第一个客户身上。
3. **它是可研，不是定稿。** 目录边界让「哪些是已定、哪些是待证」一眼可分，不必每次翻到文末找状态。

## 3. 术语（本目录内一律按此义）

| 词 | 含义 | 反例（不是这个意思） |
|---|---|---|
| **源（source）** | 一个把外部/内部世界拉平成事实的适配器 | 不是「消息队列的 producer」 |
| **事实（fact）** | 落库的一行「某对象在某时刻处于某状态」 | 不是「一条聊天消息」 |
| **规则（rule）** | 状态迁移 → 动作 → 锚 → 预算，四格 | 不是「工作流」、不是「脚本」 |
| **工作项（work item）** | 一件要关闭的事，有锚、有判据、有判决 | 不是「一个 run」（run 是它的执行实例） |
| **判决（verdict）** | 封闭枚举的结论：`pass / red / no-op-claim / needs-human` | 不是「模型的自我评价」 |
| **证据（evidence）** | 能回到原始事实的坐标（URL / sha / `file:line` / run id） | 不是「模型说它跑过了」 |
| **血统（lineage）** | 这条消息/这个 run 是被谁引起的，深度多少 | 不是「用户 id」 |
| **锚（anchor）** | 工作项挂在哪：仓库分支 / issue / 目录 / 服务 | 不是「会话 id」（会话是实现细节） |

## 4. 一页结论

1. **这个平台的重心不是「消息流转」，是「判决」。** 前者是管道（便宜、可替换），后者是护城河
   （站内八轮「绿灯不是证明」的血账，见 [03-verdict.md](03-verdict.md) §5）。**【推断，有大量既有事故支撑】**
2. **它不是 n8n、也不是 Dify。** n8n 的节点是 API 调用，我们的动作是**判据执行**；Dify 的用户造应用给别人用，
   我们的用户给自己找人干活。**别跟它们比「能连多少东西」，比「能证明什么」。** **【推断】**
3. **它与 erix-station 是上下两层，不是父子、不是 v1/v2。** station = 执行平面（让它能安全地跑起来），
   本平台 = 决策平面（让它值得跑、跑完算不算数）。**【实测：代码称重 + 导出面归类，见 01 §6】**
4. **现在不抽取底座。** 抽取的许可证不是「产品分开了」，而是**第一个「非 agent 负载」**——
   最可能是外部源的探针容器（拿凭据、不调 LLM）。它跑通的那天，底座才被证明是底座。**【推断】**
5. **两版的分裂轴是「事件源与作用对象的边界」**（系统内 / 系统外），不是「功能多少」。
   简化版 = 内部事件驱动内部资源，**零凭据、零出网、零新真相源**。**【推断】**
6. **简化版砍掉的是外部的麻烦，不是系统的麻烦。** 回环、静默不触发、观测面选错、成本失控，
   一个都没少（[05](05-feasibility.md) §3）。**【实测：站内同类事故各有先例】**
7. **宏模型（[06](06-macros.md)）是简化版的形状，不是附加功能。** 把「用户可写的规则」换成
   「管理员定义的宏 + 用户订阅」⇒ 规则语言、规则权限模型、成本不可预估**三件一起消失**。**【推断】**
8. **客户数 = 1 时，它的价值不按市场算，按「把你自己从八千行仪式里赎出多少小时」算。**
   这个判据可证伪，第一周就能验。**【推断】**

## 6. 代号

**锯脂鲤**（Serrasalmidae，食人鱼）。取的是三条性质：**群体捕食**（小 run + 多条规则，不是一个大 agent）、
**只咬有的东西**（判据驱动，不做规划）、**离开水就死**（离开牢笼/容器它什么都不是）。

选它的额外理由：食人鱼最著名的负面联想是「**失控的群体**」——那正好是本平台最怕的失败模式
（回环、成本失控、涌现出没人预料的组合）。**一个把自家失败模式写进名字的代号是诚实的代号。**

⚠ **只作内部代号。** 对外产品名需另起：`Piranha` 在英文世界已被占满（Piranha CMS / AWS Piranha /
Piranha Games），且「食人鱼平台」对企业客户有「一群失控的东西在咬我的系统」的联想。
