# 09 · 能力清单：我们能提供哪些事件、哪些动作、参数怎么设

> 状态：可研（2026-11-07）。这是宏的**词汇表**——[06](06-macros.md) 说宏是五格，本文把其中三格
> （`anchor_type` / `on_state` / `action` + 参数）填成一张**封闭清单**。
> 判据格（`criteria`）不在本文，见 [03](03-verdict.md)。

**读法**：「现在有吗」列分三档——**已有**（直接接线）/ **半有**（有零件缺一层）/ **需新建**。
每格都要能回答「它今天存在吗」，否则就是凭空设计。

---

## 1. 事件表（**四个**）

### 1.1 判据：有没有一个人，在不知道这件事的情况下会**做错决定**

比「有没有状态」和「平台能不能自己修」都更准。拿它过一遍，答案唯一：

| # | 事件 | 事实对象 | `state` 枚举（封闭） | 幂等键 | 现在有吗 | 不知道会做错什么 |
|---|---|---|---|---|---|---|
| E1 | **run 终态** | `run:<id>` | `completed` / `failed` / `capped` / `aborted` / `persistence_failed` / `guard_unverified` | `run:<id>`+state | **已有** | 以为还在跑、或以为成了 |
| E2 | **收工灯** | `dir:<path>` | `uncommitted` / `unpushed` / `never_fetched` / `no_remote` / `no_commits` / `synced` / `grey` | `dir:<path>`+state | **已有** | 以为收工了，其实没提交/没推 |
| E3 | **端口对账** | `port:<n>` | `assigned_not_listening` / `listening_not_assigned` / `duplicate_in_dir` / `stale` | `port:<n>@<pid>` | **已有**（两张表合成） | 以为预览能用，实际打不开 |
| E4 | **时钟** | `clock:<date>` | `tick`（状态型：今天还没 tick 且已过点） | `clock:<date>` | **需新建**（很小） | 以为检查过了 |

**四个事件，三个已有。** 全部是**用户的工作状态**，没有一个是平台自己的故障。

### 1.2 E3 是两张表合成的一条事件（不是两个）

| 输入 | 回答什么 | 出处 |
|---|---|---|
| `port_allocations`（号池） | 平台**分配**了哪一段 | `previewpool.js` / #256 端点 |
| `port_observations`（观测） | 容器里**实际**在听什么 | `port_observations`（#352，45s 新鲜度窗） |

**有价值的是两者的差**，不是任何一张表。`assigned_not_listening` 就是「分给你 22000，你听 3000」
——这正是 #352 已经算出来的「同一目录同时开在两个端口，多半是两个版本并存」。

⇒ 它们是**同一条事件的两个输入**，分开列会让人以为要做两个功能。
**E3 的合法动作里包含 A3（起一个 run 做号池审计）**，这是它比「通知一下」值钱的地方。

### 1.3 不进事件表的三类（各有各的去处）

**① 平台自己的故障 —— 内置告警，不可配置、不可关闭**

| 事项 | 该由谁处理 |
|---|---|
| 会话砖化（`invalid_messages`） | **平台**：读侧折叠已修（#351/#352）；存量按巡检手册修数据（要备份 + 人批） |
| 排队输入卡 `delivering` | **平台**：`CLAIM_STALE_MS` 重新认领语义已存在（#370） |
| 租约过期 / 重排耗尽 | **平台**：reaper 已在做，`attempt_killed` 已可见（#288/#292） |
| 容器镜像漂移 | **平台**：`reconcile` 的职责 |

**把平台该自己修的事做成事件，就是把平台的责任转嫁给用户。** 而且事件表会变成 bug 列表（无限长）。

**② 一条 cron / 一个管理台页面就够 —— 不需要框架**

| 事项 | 为什么不需要宏 |
|---|---|
| **证书到期**（`admin.<域>:9443` 那张，手工上传，2027-02-03 到期） | 它坏了影响的是**运维**，不是用户；只有一张、没有 N 个锚；一条定时任务发邮件给管理员即可。**它是平台的门锁，不是用户的工作** |
| **预览缺件**（`preview_miss_stats`：哪些扩展名撞 415/413，按天×ext 聚合） | 它是**统计**不是状态，回答的是「产品该支持什么格式」，**没有人会因为不知道它而做错决定**（点不开用户自己会看见）。管理台已有一页 |

**③ 现在不做**

| 事项 | 为什么 |
|---|---|
| **上游发版** | 一次性仪式、不重复；且需要语义源（简化版明确不做）。**第一版砍掉** |
| **应用不健康**（listening 但回 5xx） | 当前项目里的应用**全是开发环境**，没有生产/测试环境；dev server 每次保存都重启 ⇒ 会变成误报机。**延后到有非 dev 环境时再议** |

⚠ **这一节的教训值得单独记**：我第一版列了 12 个事件，其中**九个是从代码里搜出来的**
（`gitlight.js` / `tls-cert.js` / `port_observations` / `preview_miss_stats` / `previewpool.js` …）。
**从「系统里有什么」出发列表，一定会混进平台故障和统计数字。** 正确顺序是反过来：
先问「谁需要被叫醒」，再去代码里找能不能算出来。

## 2. 动作表（平台能做什么）

> ⚠ 本节 12 个动作**都是「做事」**，不是「修自己」。修自己的动作（重建容器 / 改证书 / 改 LLM 绑定）
> 之所以在表里，是因为它们对**运维宏**合法（E3 证书到期 → A10 换证），不是因为它们是平台自愈手段。

| # | 动作 | 类型 | 参数 | 现在有吗 |
|---|---|---|---|---|
| A1 | **投一句话到会话** | 通知 | `session`（锚解析）/ `text`（模板）/ `role`（默认 `user`） | **已有**（`postMessage`） |
| A2 | **新建会话** | 通知 | `cwd` / `title`(≤200) / `model`(≤100) / `origin` | **半有**（`createSession` 有前三个，**无 `origin`**） |
| A3 | **起一个 run** | 任务 | `cwd` / `task`（模板）/ `maxRounds` / `session`（新建或复用） | **已有**（= A2 + A1 + 队列） |
| A4 | **发邮件** | 通知 | `to`（**枚举**，见 §2.2）/ `subject` / `text`（纯文本） | **半有**（`mailer.send({to,subject,text})` 有，只用于验证码，缺「通知用」路径与模板） |
| A5 | **站内通知** | 通知 | `user` / `title` / `body` / `link` | **需新建**（小，但需要一个 UI 落点） |
| A6 | **平台落盘** | 通知 | `path`（模板，限 `~/reports/…`）/ `content`（= run 的 `final_text`） | **需新建**（小；平台不受 jail 限制，见 [08](08-scheduled-and-sessions.md) §1） |
| A7 | **停 run** | 控制 | `run` / `reason` | **已有** |
| A8 | **重建容器** | 运维 | `fde` / `image`(digest) | **已有**（`provisioner`） |
| A9 | **签预览票** | 运维 | `allocation` / `ttl` | **已有**（`/api/me/ports/batch-tickets`） |
| A10 | **改证书** | 运维 | `certPem` / `keyPem` / `confirmDomains` | **已有**（`PUT /api/admin/tls`） |
| A11 | **改 LLM 绑定/白名单** | 运维 | `fde` / `models[]` / `budget` | **已有**（`/key/update`） |
| A12 | **写档案（note）** | 通知 | `scope`（**今天只有 `sessionId`**）/ `key` / `text` | **半有**（缺 `user` / `dir` scope） |

### 2.1 三个「类型」的含义

| 类型 | 起 run 吗 | 成本 | 失败要不要通知 |
|---|---|---|---|
| **通知** | ❌ | ≈0 | 失败静默可接受（它本身不产生价值，只是搬运） |
| **任务** | ✅ | 一个 run | **必须通知**（[08](08-scheduled-and-sessions.md) §6） |
| **控制/运维** | ❌ | ≈0 | **必须通知**（它改的是系统状态） |

⚠ 这不是分类癖：**「任务型失败必须自己会说话」是 [08](08-scheduled-and-sessions.md) §6 那第四种静默死法的唯一防线**。

### 2.2 参数只许六种类型（这是「不需要规则语言」的代价）

| 类型 | 约束 | 例 |
|---|---|---|
| `enum` | 封闭取值 | `to` / `model` / `role` |
| `path` | 必须落在 jail 或 userspace 白名单内，且**不允许 `..`** | `cwd` / `path` |
| `int` | 带上下界 | `maxRounds`(1–100) / `ttl`(≤600) |
| `duration` | `Ns`/`Nm`/`Nh`，有上限 | `quiet_hours` / `jitter` |
| `text` | 长度上限 + **只能引用白名单变量**（§2.3） | `text` / `subject` / `title` |
| `email` | **只能从枚举里选**，不接受自由填写 | `to` |

### 2.3 模板变量白名单（**这是唯一的小语言，必须极小**）

```
{{anchor}}     锚的可读名（目录名 / 仓库名 / 端口号 / 会话标题）
{{state}}      本次命中的 state 字面值
{{evidence}}   证据摘要（源给的，纯文本，≤500 字）
{{date}}       本地日期（UTC+8，YYYY-MM-DD）
{{run_id}}     触发本次动作的 run（任务型才有）
{{url}}        可点的落点（预览地址 / 管理台链接）
```

**没有条件、没有循环、没有函数、没有算术。** 认不出的变量 ⇒ **渲染失败 + 记一笔**，
不许原样输出 `{{xxx}}`（那会把内部变量名漏给用户）。

⚠ **收件人必须是枚举**（`当前用户` / `管理员` / `自定义白名单`），**不许自由填邮箱**。
否则「一个宏」= 「一台发信机」，而这个系统里任何能写规则的人都能用。

## 3. 三个必须一起定的边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **动作必须可逆或可解释** | `A8` 重建容器会**打断正在跑的 run**；`A10` 改证书能把自己锁在门外（[#462](07-scenarios.md)）。⇒ 这类动作要 `destructive: true` + 默认不启用 |
| 2 | **动作不许写外部系统**（[05](05-feasibility.md) §4.1） | 边界是「谁的渠道」：`A4`/`A5`/`A6` 走平台自己的渠道 ⇒ 可以；在 GitHub 评论 ⇒ 不行 |
| 3 | **`criteria` 不能为空就宣布成功** | 通知型动作（A1/A4/A5/A6）**本来就没有判据**，那是正常的；但**任务型（A3）必须有判据**，否则「跑完了」= 「成了」，那就是 `no-op-claim` |

## 4. 覆盖度自查：4 个事件 × 12 个动作

| 事实对象 | 能用的事件 | 能用的动作 |
|---|---|---|
| `run` | E1 | A1 A4 A5 A6 A7 |
| `dir` | E2 E3 | A1 A3 A4 A5 A6 A12 |
| `port` | E3 | A1 A3 A4 A5 A9 |
| `clock` | E4 | A3 A4 A5 A6 |

**≈18 个合法组合。** 这是「不需要规则语言」最硬的证据——18 个组合，
每一个都能写成一条具名宏、被单独测试、被变异验证。一门表达式语言在这种规模上只会增加不透明度。

⚠ **注意「会话」不在这一列**：它**不是事实对象**，是**作用域**（我允许这个宏盯我哪些东西）
与**投递目标**（通知落在哪）。事实是 `run` / `dir` / `port` / `clock`。

## 5. 所以「参数怎么设」的完整答案

以用户举的两个例子收尾：

```
宏：任务完成 → 发邮件
  anchor_type   用户（作用域 = 我的所有会话）
  on_state      E1: run.completed
  action        A4 发邮件
    to          enum: 当前用户           ← 不是自由邮箱
    subject     text: "[{{anchor}}] 任务完成 · {{date}}"
    text        text: "{{evidence}}\n\n查看：{{url}}"
  criteria      （空 —— 通知型不需要）
  budget        max_per_day 20 / quiet_hours 22:00-08:00
  notify_on_failure  true

宏：每天打卡 → 开新会话跑活
  anchor_type   用户
  on_state      E7: clock.tick
  action        A3 起一个 run
    session     新建（title = "{{date}} 每日检查"，origin = macro:daily-check）
    cwd         path: ~/projects/<项目>   ← 由订阅时选，不是模板变量
    task        text: 固定任务描述（模板）
    maxRounds   int: 16
  criteria      见 [07](07-scenarios.md) §5 判据②③
  budget        max_per_day 1 / jitter ±10m
  notify_on_failure  true
```
