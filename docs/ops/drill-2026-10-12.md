## 六、操作坑（这轮新踩的，省下一个人的时间）

- **项目级 playwright 容器（:8935）的 MCP 版本参数名与默认实例不同**：点击/填表用 **`target`**（不是 `ref`）；`browser_console_messages` **必须给 `level`**；`browser_network_requests` **必须给 `static`**；`browser_take_screenshot` **必须给 `scale`**。默认实例（8931）不吃这些参数名，照旧记录写会一路报错。
- `POST /api/ports/:id/preview-ticket` 要求 **`Content-Type: application/json`**（文档写「无体（空 JSON `{}`）」）。上一轮文档里我给的 curl 片段少了这个头，照抄会 400——已在本文更正。
- `POST /api/sessions/:id/messages` 的字段是 **`content`**（不是 `text`）；`POST /api/admin/users` 的 `email` 必填。
- 预览票据 **60 秒**过期：在浏览器里排多步操作时，签完立刻用；跨 host 的 API 调用要**各 host 各有一票**（先访问后端 host 换 cookie）。
- `bash` 里 `UID` 是只读变量（上一轮踩过，这轮又差点踩）；`psql` 里 JSONB 取值要整体加括号。

### 真机才抓得到的：cookie 会话在预览域名「写通读不通」

浏览器里注册成功、登录后一切后续请求都回「未登录」；容器内同 sid `curl` 却是 200。裸 echo 探针（22034，经边缘）给出决定性对照：

```
GET  /  →  COOKIES=None
POST /  →  COOKIES=sid=DEADBEEF
```

**Traefik v3 `headers.customRequestHeaders` 的 `Cookie: ""` 只对 GET/HEAD 生效，POST/PUT/PATCH 原样透传**——
`strip-cookie`（fde-platform §6.4 B2，当年 whoami 实跑「验证过」）只实现了承诺的读方法半边。后果分两层：

> ⚠ **本小节的「半通」定性当晚稍后被证伪（#263 已关闭，见其更正评论）**：三重独立复测（同版本
> `traefik:v3.7.13` 干净试验台 + 现网边缘 + 官方文档）均为「**全方法一致剥除 Cookie 头**」。
> 上文 `POST → COOKIES=sid=DEADBEEF` 是一次无法复现的观测（具体成因已不可重建）。真正成因平凡得多：
> 登录 POST 从**请求体**拿凭据、用 `Set-Cookie`（**响应**头，边缘不动）种会话 ⇒「写」当然通；
> 之后一切**读 cookie** 的请求（GET 与带 cookie 的 POST 一样）被剥光 ⇒「读」必死。
> ⇒ 结论修正：**平台实现与 B2 承诺一致，不是 bug；缺口只在告知面（#262，按全剥口径修）**。
> 保留的教训升级为本仓库纪律：**探针只打单边方法就会得出错误的层结论**——双向（读+写）探针
> 已成预览相关断言的硬性组成（转办 #227）。


1. **告知面缺口（#262）**：六条链没告诉应用「自己的登录态别用 cookie」。r2-app（cookie 会话）死；R-1 的 r1-app（Authorization 头）活——同一条链一死一活纯靠选型运气。agent 在容器内测不出（不过边缘），21/21 全绿不是巧合（POST 通、GET 死）。
2. ~~**平台实现 bug（#263）**：剥 cookie 该用 request-regex 中间件（全方法一致），或改口径只剥平台 cookie~~
   ——**已证伪撤单**（#263 以 not_planned 关闭；且 v3 本无 regex 头改写中间件，原 A 方案根本落不了地——盲修会把不存在的能力当现成的用，这也是本小节留下的一条反面教材）。
