> 面向：主 agent / 运维 / 下一个进这个仓库的人。
> 性质：**演练（drill）记录**，不是规格。规格看 `docs/design/fde-platform.md`；部署现状看 `docs/ops/deployment-2026-10-10.md`；CI/发布看 `docs/ops/ci-release.md`。

## 一、演练判据与结论

| 判据 | 结果 |
|---|---|
| 管理员建用户（带 FDE 名）→ 自动开户（网络 / 容器 / 预览域名 / LLM 绑定） | ✅ |

| 用该平台**自己的 agent**在平台里写一个**前后端分离**的多用户俄罗斯方块（前端 dev server + 后端 API） | ✅ 会话 `b35109c0…`共 3 个 run；写应用的 run `f4dfea1d…` = **32 轮 / ↑926,290 ↓39,158 / `judge_done`**；应用仓 `tetris-arena` **5 次提交已全部推到 `origin/main`** |
| 多次 push 到 Gitea 后，应用在**测试环境**（预览域名）真的能访问、前后端真的联通 | ✅（经两轮平台侧修复之后） |
| 人（非 curl 高手）能不能自己拿到预览链接 | ❌ **仍是缺口** → #246 交付② 单 B（UI）在做 |

**一句话结论**：链路本身是通的，但**断点全部不在"agent 会不会写代码"，而在宿主侧的可见性与鉴权边缘**——预览域名没有列表 API、CORS 预检被鉴权吃掉、端口是硬编码约定。这三件事都不修，用户的第一次体验就是「应用写完了但打不开」。

## 二、「前后端分离为什么跑不起来」的真实原因链（#241）

现象：前端 `http://tetris-p-22010.…:8090`、后端 `http://tetris-p-22011.…:8090`，浏览器里**只要请求带 `Authorization` 就必挂**，报 `No 'Access-Control-Allow-Origin'`，看起来像应用 CORS 配错。

实测定位（当时的证据）：

1. **同站跨源 + `credentials: 'include'` 是好的**：`preview_test` 是 `SameSite=Lax` 的 **host-only** cookie，两个预览 host 同在 `.fde.erix.vip` 站下 ⇒ Lax 照样发送。裸 `fetch(后端)` 返回 `200`、`Access-Control-Allow-Credentials: true`。
2. 一旦加 `Authorization: Bearer x` ⇒ **必挂**：浏览器按 Fetch 规范先发 **CORS 预检 `OPTIONS`**，而**预检不携带任何凭据**。
3. 平台把 `OPTIONS` 和普通请求一样送去 forwardAuth ⇒ 无票据 ⇒ `403`，而这个 `403` **不带任何 CORS 响应头** ⇒ 浏览器报「缺 ACAO」。
   ⇒ **平台的「需要预览票据」被伪装成了「你的应用 CORS 配错了」**。这是演练里最容易误诊的一条。

修法（PR #244，口径已进 `AGENTS.md §8.11`）：① `OPTIONS` **且**带非空 `Access-Control-Request-Method` 只免**凭证/exposure** 判定，未知 host `404`、已释放 `403` 照旧；② deny（401/403/404）一律回显 `Access-Control-Allow-Origin` + `Allow-Credentials` + `Vary: Origin`。落点选 portal 不选边缘的原因（实测 `traefik:v3.7.13` 会透传 auth 子响应的头；边缘 `Add` 会和 dev server 自带的 ACAO 叠成两个值）也写在同一节。

⚠ **最容易复发的坑**：`forwardAuth.authRequestHeaders` 是**白名单**。portal 想读 `Origin` / `Access-Control-Request-Method` 就必须同时改生成器 `portal/src/routes.js`；只改 portal 会**默默失效**。

## 三、端口与预览域名：演练把三处认知纠正了

| 原先的认知 | 真机纠正后 | 单 |
|---|---|---|
| 端口是「应用自己挑、平台不感知」 | 容器内 `~/.erix/ports.json` **是唯一真相**（旧记录说的 `deploy/ports.json` 路径根本不存在）；SYSTEM_PROMPT 要命令 agent 读它 | #240 |
| 开户时预分配、端口固定 `4000–4009` | 全局号池 **`22000–29999`（800 段）**，按 FDE 顺序发**对齐的 10 个一段**；**重叠是 DB 保证的**（迁移 0019 的 `UNIQUE (port) WHERE state<>'released'`），不是应用保证的 | #246 交付① |
| 已有 allocation 就能「改配置」 | `ensureFdePreviewPorts` 是 **insert-only** ⇒ 改块必须是**搬迁事务**（释放旧段 + 撤凭证 + 插新段 + 入队派生链，失败整笔回滚）；`released` 不占位 ⇒ **号码可回收**（真机 `22000→22030→22000` 各一次） | #246 交付② 单 A |

另外登记了一条**静默数据缺陷**（#252，已修）：撤预览凭证的谓词写成 `state IN ('active','used')`，而 `preview_grants` 的 CHECK 是**双向**的 `((state='used') = (used_at IS NOT NULL))` ⇒ 真机 45 条已消费的 ticket **一改就 `23514`**；同一条谓词在 offboarding 里还挂在「本次是否释放了行」的守卫上 ⇒ **重试时整段跳过撤权**，留下 21 条残渣而步骤记 `done`。教训与判据已写进 `AGENTS.md §8.14`：**声称「测试 fake 拦得住」必须附变异测试结果**。

## 四、操作手册片段（可复制）

```bash
B=http://station.fde.erix.vip:8090
R=(--noproxy '*' --resolve station.fde.erix.vip:8090:127.0.0.1)     # 本机解析器有负缓存，必须 --resolve

# 登录（注意是 /api/auth/login；/api/login 只是 307 跳板；口令别放命令行——进 shell history）
curl -sS "${R[@]}" -c /tmp/adm.jar -X POST -H 'content-type: application/json' \
  -d '{"login":"admin","password":"…"}' "$B/api/auth/login"

# 列端口（列表里的 id 就是签票入参）
curl -sS "${R[@]}" -b /tmp/adm.jar "$B/api/me/ports"
curl -sS "${R[@]}" -b /tmp/adm.jar "$B/api/admin/fdes/tetris/ports"

# 签票 → 带 cookie 走完 302（-c 也要给，否则 Set-Cookie 丢在终端里，第二次请求等于无票）
# 签票端点要求 `Content-Type: application/json`（文档写「无体（空 JSON `{}`）」）；不带这个头会 400
T=$(curl -sS "${R[@]}" -b /tmp/adm.jar -X POST -H 'content-type: application/json' -d '{}' "$B/api/ports/<allocation-id>/preview-ticket" | jq -r .ticket)
curl -sS --noproxy '*' --resolve tetris-p-22010.fde.erix.vip:8090:127.0.0.1 -c /tmp/t.jar -b /tmp/t.jar \
  -o /dev/null -w '%{http_code} %{redirect_url}\n' "http://tetris-p-22010.fde.erix.vip:8090/?preview_ticket=$T"

# 管理员改块（会让他手里的旧链接立刻 404，先确认再发）
curl -sS "${R[@]}" -b /tmp/adm.jar -X POST -H 'content-type: application/json' \
  -d '{"block_start":22030}' "$B/api/admin/fdes/eric/ports/block"

# 预览凭证残渣巡检（应为 0；>0 说明有 offboarding 半截失败，跑迁移 0020 即可，零 DDL 可重放）
docker exec station-db psql -U station -d station -c \
  "select count(*) from preview_grants pg join port_allocations pa on pa.id=pg.allocation_id \
    where pg.state='active' and pa.state='released'"

# 号池现状（重叠必须为空——0019 的 DB 不变式）
docker exec station-db psql -U station -d station -tAc \
  "select u.fde_name,min(a.port)||'-'||max(a.port) from port_allocations a join users u on u.id=a.fde_id \
     where a.state<>'released' group by 1 order by 1"
```

**FDE 容器内**（agent 视角）：`cat ~/.erix/ports.json` —— 顶层键是 **`allocations`**（不是 `ports`），每次改段/重建 `generation` 会递增。tetris 那次改号之后，平台自己的 agent 就是自己读这个文件把 `config.js` 里的后端 URL 改对并 push 的（run `87a31661…`，66 轮，↑1,228,068 / ↓12,817，`judge_done`；对应提交 `31a8cb3 chore: 适配平台动态端口分配…`）——这是「告知面正确 ⇒ agent 能自愈」的正面证据。

## 五、演练里踩到的操作坑（省下一个人的时间）

- **`curl -L` 不带 cookie jar 等于没签票**（302 的 `Set-Cookie` 被丢弃）；`--resolve` 必须写满 `host:port:ip` 三段。
- **`-c http.proxy=` 会被 curl 当成「写一个叫 `http.proxy=` 的 cookie jar」**（本仓库根目录一度出现两个 131B 的垃圾文件）。`-c` 是 cookie jar，`-x` 才是代理。
- `curl -o /tmp/x.json -w '%{http_code}'` 里 `-w` 的值必须**紧跟选项**，写成 `-w ' …'` 会把空格后的内容当第二个 URL。
- `docker exec` 的 `HOME` 是空的 → 容器里跑 node CLI 要 `-e HOME=/home/erix`（`--user` 数值 id 同理）。
- `bash` 里 `UID` 是**只读变量**，`UID=$(…)` 静默失败 → 后面拿到 `0` 当 user id 用，报 400。
- `psql -c "select '标签='||col from …"` 里 `||` 与 `->>` 的优先级：JSONB 取值要**整体加括号** `(('{'…'}')::jsonb->>'k')`，否则报 `operator does not exist: text -> unknown`。
- 本机解析器对 `fde.erix.vip` 有**负缓存**（路由器 DNS），curl 用 `--resolve` 兜，浏览器用 `erix_station_playwright`（:8935，带 `--host-resolver-rules=MAP * 100.100.0.3, EXCLUDE localhost`）。
- FDE 容器**没有 `curl`**（只有 node），要探链路就在宿主做。
- **模模型侧的坑（#243，开放）**：run `f4dfea1d…` 正常以 `finished` 结束，但**最后一条 assistant 消息不是结论，而是模型把工具调用文本化进 `content`**：`<｜｜DSML｜｜tool_calls><｜｜DSML｜｜invoke name="shell">…`。用户在工作台看到的「最终回复」就是这堆标记 ⇒ **等于没交报告**。⚠ **它是静默发生的**：`termination.reason` 仍是正常值，`run_events` 里**没有任何可辨识信号**（该表实际只有 12 种类型：`assistant_delta / attempt / judge / model_metadata_missing / reasoning_delta / round_end / round_start / run_end / run_outcome / tool_call_delta / tool_result / tool_use`；**平台侧不存在所谓的 `model_no_tool_call` 事件**）。平台侧不加重试（幂等无法界定），要的是**信号**，验收口径见 #243。
