# 05 · 可研：要证什么、怎么证、什么情况判「不值得做」

> 状态：可研（2026-11-07）。**本文件是可研的交付物本体——不是代码，是五条可证伪的判断。**
> 前四篇（[01](01-positioning.md)–[04](04-scope.md)）是结论与模型，本篇是「凭什么信它」。

---

## 1. 可研的交付物不是代码

因为 `erix-station` 要做大升级，本项目的正确产出是**一组能用现有代码/数据回答的问题**，
而不是一个原型。理由：原型会腐烂，问题不会；而这些问题每一个的取证成本都在一小时以内。

## 2. 五条待证命题

| # | 命题 | 怎么证（便宜） | 判据（什么算证成） |
|---|---|---|---|
| **1** | **内部事件面足够表达「值得自动化的仪式」** | 把 `AGENTS.md` 里所有人工仪式逐条翻译成「事件 + 谓词 + 动作 + 锚 + 预算」 | 能翻译的比例 ≥ 多数；**翻不出来的那些本身就是「这平台做不到什么」的清单**（比任何架构图都有用） |
| **2** | **最贵的那几条仪式真的能被自动执行** | 挑**一条**，人工跑一次，把它的判据写成配置文件 | 判据能只用「命令 + 退出码 + 坐标比对」表达，不需要模型参与判断 |
| **3** | **回环与成本可控** | 数「一次 run 终态会命中几条规则」，乘 run 成本，算最坏一天 | 最坏值在你愿意付的钱之内；且深度上限能真的掐住 |
| **4** | **判据能被执行而不只是被描述** | 取一条现有判据（如「跑测试只认退出码」），检查它的输入面 | 只需「一条命令 + 一个退出码 + 一份声明清单」；**需要服务端上下文/跨会话记忆才能表达的，就不是判据，是判断** |
| **5** | **「被赎出多少小时」可度量** | 设计一个能记账的地方：每条规则命中几次、花了多少、人是否因此少做一步 | 能回答「上周这套东西替我做了什么」；答不出来就等于没做 |

### 2.1 命题 1 的做法（最有价值的一条）

不要写文档，**做一张表**：`AGENTS.md` 的每一节 → 它现在靠什么触发 → 它要什么判据 → 它落在哪个锚。

副产品会非常有价值：

- **翻不出来的那些节** = 「这平台做不到什么」的诚实清单（比如「判断这个设计对不对」翻不出来，
  因为它没有判据——那是 `needs-human`）。
- **翻出来但判据依赖模型的那些** = 语义源的候选清单（同时也是成本清单）。
- **翻出来但今天没有任何事件源的** = 要新造源的最小集合（我预期这个集合很小，因为
  [04](04-scope.md) §2 那十个源已经覆盖了大部分）。

### 2.2 第一个垂直切片：上游发版 → 该不该升 → 派活

**不用「名人去世 → 写悼文」**——那是极好的演示，但**演示不能证伪**。这个切片能：

```
源①  npm dist-tags.latest              机械 · 免费 · 一分钟一次
       state: unchanged | new-version
源②  「这次升级对本仓会红几格」          语义 · 一次 run · 必须带 evidence
       state: trivial | breaking | blocked-by-上游未发版   ← 封闭枚举
       evidence: 读了哪两个包目录 diff、哪几条判据翻红、npm pack 的 shasum
动作   trivial → 起一个升 pin 的 run
       breaking → 通知人并附证据
       blocked → 静默退避
```

它同时验证：机械源产事件、语义源产**带证据的判断**、`state` 枚举挡住模型自由发挥、
三档动作各走不同通道、退避与幂等都有真实对象。

**而且它立刻有用**——站内为「上游发版了没 / 能不能升 / 升了会怎样」写过至少三篇长考据
（§8.60 / §8.86 / §8.90），其中 §8.86 那次甚至抓到**上游文档说删了 16 个导出、npm 上实际一个没删**，
得自己 `npm pack` 对 `dist.shasum` 才敢下结论。**这就是「不信文档、要证据」的标本**，
也是这个切片存在的理由。

## 3. 五个硬问题（简化版一个都没躲开）

### 3.1 回环（内部版更危险）

规则起 run → run 终态 → 触发规则。**周期是秒级、在同一张表里、因果链看不见。**
外部版至少还隔着分钟级的外部系统，内部版没有这层缓冲。

站内已有血统位：`runs.trigger_kind` 的 `'synthetic'` **运行时零使用**（迁移预留、一直空着，
本轮全仓 grep 只在 `0024-queued-inputs.sql` 的 CHECK 里出现）。
**它必须进谓词，不能只落库好看。** 另加 `causal_id` 深度上限兜住「没想到的回环」。

### 3.2 静默不触发（三种形态，本站最高频死法）

| 形态 | 实例 |
|---|---|
| 库里存着，读不出来 | #371-A |
| 配了，没人读 | #331（下发但零读取 = 死光纤） |
| **判据落在错误的观测面上** | §8.87（两次把「0 条 `compaction` 事件」当「TTL 层没工作」，而 TTL 层**根本不发那个事件**；真相在 `compactionStats`，75 次触发省 31.4 万 token） |

第三种最危险，因为它**看起来有数据**。那次错误的代价不是返工，是**差点建议撤掉一个正在省 31 万 token 的配置**。

### 3.3 事件比执行快

`capacity=1` 串行 + 每会话单活跃 run，而事件不会因为你忙就少来。十个会话同时终态就会堆。
⇒ 源侧退避 + 总线侧背压 + 规则侧丢弃陈旧（[02](02-model.md) §10）。

### 3.4 规则即平台代码

简化版的规则是我们自己写的（省掉了权限模型，这是巨大优势），代价是
**规则的每次修改都等于改平台** ⇒ 需要和代码同等的审查纪律：变异测试、判据随 run 快照、判据落在具名用例上。

### 3.5 「有用」无法自证

外部版有采用率，内部版只能靠「被赎出多少小时」。这需要一个**可判的**度量（命题 5），
否则做完之后无法回答「这套东西值不值」——而那是最容易变成「做完就没人再提」的死法。

## 4. 已知边界与不做清单

### 4.1 本平台明确不做

| 不做 | 理由 |
|---|---|
| 消息中间件 / 内存总线 | 站内总线已经是 DB；再引入一个 = 第二个真相源，违反「DB 是状态真相」 |
| 可视化编排器 / 表达式 / DAG | 那是变成 n8n 的唯一路径（[01](01-positioning.md) §5） |
| 公网 webhook 入口（第一版） | 现网用户面仍是明文 HTTP；投递入口是拓扑级的事。先轮询 + 容器侧探测，零暴露 |
| 语义源（简化版） | 要 jail + 钱 + 账本，三件都没有 |
| 平台写外部系统（第一版） | 边界是「**谁的渠道**」，不是「出了容器没有」：发邮件 / 站内通知走平台自己的渠道（`mail_settings` / `users.email` 已有）⇒ **可以做**；在 GitHub/Gitea 上评论留痕是写**别人的**系统且会暴露平台身份 ⇒ 仍延后，要单独裁决 |
| 自己的一套身份 | 一旦有第二个登录页，就有两套权限、两套「这个人能看到什么」 |
| 抽 L0 底座 | 许可证是「第一个非 agent 负载」（[01](01-positioning.md) §6.6），不是「产品分开了」 |

### 4.2 已知的、必须先解的空缺

1. **跨会话的机器档案放哪**：notes 作用域是 `sessionId`，而「issue / 分支 / 名人」这些对象跨会话。
   **它是 agent-as-source 的硬前置**，不是细节。
2. **`/api/internal/*` 零版本标记**：三产物之前必须先有它，否则契约破了不会响，只会静默出错。
3. **station 没有给「平台级消费者」的事件出口**：SSE 绑 session 且要登录 cookie。今天只能轮询 `runs` 表。
   正解是照抄站内已有的 `route_outbox` / `materialize_outbox` 那套 **outbox 表**（已有两处同型先例）。
4. **`runs.actor` 与 `runs.trigger_kind` 必须分开**：前者是执行者，后者是发起者，一个 `user_send` 的 run
   完全可以由某个员工执行。合成一列则「员工干的、人发起的活」永远分不出来。

### 4.3 一条硬边界：能力而非密钥

station 今天**容器里不放平台密钥**（git 凭据是只读 bind、LLM 是边缘注入的 per-FDE 虚拟 key）。
这个设计在通用平台上反而更强——**员工拿到的是一个被裁剪的能力，不是一个秘密**。
⇒ 通用化时**不许退化成「往容器里塞 token」**。

## 5. 结论标准（提前写好，免得事后找理由）

可研结束时按这三档判：

| 判定 | 触发条件 |
|---|---|
| **值得做（按简化版）** | 命题 1 能翻译出**多数**仪式；命题 2 至少一条判据能纯机械表达；命题 3 的最坏日成本可接受；命题 5 能给出一个可读的周报 |
| **缩小范围** | 命题 1 只能翻译出少数、且集中在**同一族**（例如全是「部署核对」类）⇒ 那就只做那一族，别做平台 |
| **不值得做** | 命题 2 失败（判据都需要模型判断）**或**命题 3 最坏成本不可接受 **或** 命题 5 无法度量 |

⚠ **一条反直觉的顺序**：命题 5（可度量）比命题 2（能执行）更该先做。
因为「做完发现没法证明它有用」是这类内部工具最常见的死法，而它的成本只是**设计一个记账位置**。

## 6. 本次可研的自我边界

按站内纪律（「结论分档、二手不等于事实」），本目录全部结论的来源分三档：

| 档 | 内容 |
|---|---|
| **【实测】**（本轮在仓库/真机上查证） | `internal.js` 导出面 52 个 = 25 通用 / 23 引擎形状 / 4 产品；`portal/src` 按职能行数（6120 / 6550 / 2519 / 2955 / 约 6900）；`trigger_kind` 四个值与 `synthetic` 运行时零使用；`/api/internal/*` 无版本标记；`docs/data/schema.sql` 是 sha256 冻结 baseline + 单一迁移流；`port_observations` 通道五件性质；`reapExpiredRuns` 三条分支与 `killed_by` 保守取 `crash`；`queued-inputs` 的 CAS / 过期重认领 / 五处终态调用 / `not_deliverable_at_terminal`；`worker.js` 工具面是恒定扁平全集；#363 三层 skill 通道；§8.87 的 `compactionStats` 与 31.4 万 token；#391 的空集合恒真 |
| **【推断】**（按原理推导，未验证） | 「判决是护城河」；两版分裂轴选「事件源边界」优于「谁提供执行」；「一个非 agent 负载」作为 L0 的许可证；「加员工的边际收益在验收带宽处归零」；第一个垂直切片选「上游发版」 |
| **【未验】**（本目录明确没做的） | 没有跑任何原型；没有测过任何一条规则的真实命中率与成本；没有验证过「用配置文件表达判据」的可行性（命题 2 未做）；没有验证「跨会话档案」的任何设计；没有评估过 dashboard 的具体形态 |

⇒ **本目录的定位是「一组想清楚的问题 + 一份可执行的取证计划」，不是「一个已验证的结论」。**
任何一条【推断】在被【实测】替代之前，都不该被当成设计依据写进代码。
