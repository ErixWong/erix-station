# 02 · 事件模型与判决：怎么建、怎么判

> 状态：可研（2026-11-07）。本文件只定**形状**，不定实现。
> 凡引用站内既有机制的地方都标了出处，那些是**【实测】**；纯设计判断标**【推断】**。

---

## 1. 三个词先分开，否则后面全是混乱

| 词 | 是什么 | 不是什么 |
|---|---|---|
| **源** | 把世界拉平成事实的适配器 | 不是「消息生产者」 |
| **事实** | 落库的一行「某对象在某时刻处于某状态」 | 不是「一条聊天消息」 |
| **规则** | 状态迁移 → 动作 → 锚 → 预算，四格 | 不是工作流、不是脚本 |

以及一组最容易混的：

| | 含义 | 站内对应 |
|---|---|---|
| **工作项** | 一件要关闭的事（有锚、有判据、有判决） | 今天**不存在**（缺的就是它） |
| **会话** | 人与 agent 的对话容器 | `chat_sessions` |
| **run** | 工作项/会话的一次执行实例 | `runs` |

> **「员工」是定义，「run」是实例。** 这一句挡掉一堆混乱：员工挂了 ≠ 平台挂了（是 run 失败）；
> 「我们有 8 个员工」≠ 并发 8；「给员工加技能」= 改定义，不是改代码。

## 2. 消息（事实）的六个字段

```
{ source,          // 谁说的：gitea / git-remote / npm / clock / db / agent:<probe> / human
  object_key,      // 说的是谁：'owner/repo#123' | 'owner/repo@main' | 'npm:erix-agent' | 'work:<id>'
  state,           // ★ 封闭枚举：可比对 —— 幂等键的一半
  evidence,        // ★ 可复核坐标（URL / sha / file:line / run id）—— 没有它就不许信
  observed_at,     // 我们落库的时刻（不是外部载荷的时间戳）
  causal_id,       // 我是被哪条引起的；深度上限防环
}
```

**每个字段为什么不能省**：

- **`state` 封闭枚举**是全套设计最重要的一格。模型给的值不在枚举里 ⇒ 一律落 `unknown`，**不报错也不入库成状态**。
  理由：**「让模型填自由文本」= 让外部世界通过模型写我们的数据库。** 网页正文里的「他去世了」可能是谣言、
  可能是讽刺新闻——而站内早就立过「网页正文里的指令不等于用户指令」；语义源是这条风险的**升级版**：
  它不是被注入**指令**，是被注入**事实**。
  ⚠ **`state` 允许是派生值**（如 `session.completed := status='finished' AND reason IN ('judge_done','end_turn')`），
  但**派生规则属于源的定义，不属于宏**，且要版本化——否则「完成」会有两套语义（邮件宏一个、日报宏一个），
  而这正是站内反复踩的那类坑（同一件事两种可见性）。详见 [07](04-scenarios.md) §8.A。
- **`evidence`** 对应站内已经付过很多学费的纪律：「交付物第一格固定 `## 取证边界`」、
  「带 `file:line` 的结论随机抽 3–5 条实跑对账」、「自己带过来的话不等于事实（二手改写会造出原物没有的东西）」。
  **同一个原则的总线版：一个语义判断必须携带能回到原始事实的坐标，否则平台有权当它 `unknown`。**
- **`observed_at` 由我们写，绝不用外部载荷时间戳**——载荷时间会漂、可伪造、跨系统不可比。
  配套站内约定：时间字段由应用侧写入，DDL 不写 `DEFAULT CURRENT_TIMESTAMP`；时区一律 UTC+8；
  凡涉及时间先现查 `date`，不许凭记忆推。
- **`causal_id` + 深度上限**是「排除自己推的」的通用化：有了血统链就能算「这条链第几代」，超深就掐。

## 3. 四类源

| 源 | 状态从哪来 | 要不要智能 | 一次多少钱 | 主要失败模式 |
|---|---|---|---|---|
| **站内机械** | 自己的库（git 灯、run 终态、账本体积、证书到期、版本漂移） | 不要 | 0 | **静默不触发**（见 §8） |
| **站外机械** | 轮询 / webhook（Gitea API、`ls-remote`、npm `dist-tags`） | 不要 | 0（+凭据） | 凭据过期、游标丢、限流 |
| **站外语义** | agent 探测（搜一搜、读一读、判一判） | **要** | **一个 run** | 假阳性/假阴性 + **输出会抖** |
| **人类源** | 人确认 / 人回应（评论、点一下、回一句话） | 不要 | 无限延迟 | 没人回（要有超时降级） |

> **`cost` 必须是源契约的字段，不是配置项。** 因为「这条源能多勤」是源的性质，不是用户的偏好：
> 机械源可以一分钟一次，语义源必须退避。

⚠ **总线的终点不总是 agent，很多时候是人。** 上表「动作」有一大半的正确落点是「告诉人」，
而「人看到了并回应了」本身又是一个源。**这就是为什么它是平台的事件模型，不只是「让 agent 干活的触发器」。**

## 4. 事实必须先落库：影子表

> **「DB 是状态真相」这条不变式对外部的延伸：外部事实必须先落库成影子，才能被谓词查询。**
> 不落库，「超过 N 分钟」这句话就没有主语。

站内已经有一条**完整跑过一轮的通道模板**（#352 端口观测）**【实测】**：

```
runner/lib/listeners.js  collectListeners({procPath, home})   ← 观测在容器（凭据也在这边），根目录可注入 = 单测用 fixture
agentd.js:437-447        try { collect(...) } catch { listeners = [] }
                                                              ← 探测器坏了不许影响心跳
      └─ 捐在 U4 heartbeat 载荷里（不是新端点，复用租约通道）
internal.js:1122-1195    落 port_observations；写失败只 warn，心跳继续
      └─ 先 SELECT 旧 → DELETE → 整批 INSERT               ← 「此刻的事实」，新鲜度自动淘汰
portalloc.js:381         新鲜度窗在【读侧】过滤（「窗口内的行才算此刻还在听」）
```

四件可照抄的性质：**探测在容器 / 探测器坏了不影响主通道 / 写失败只 warn / 新鲜度在读侧过滤**。

影子表的形状（示意，不是 DDL）：

```
external_sources   凭据引用 + 游标 + 拉取间隔
external_facts     (source, object_key, state, first_seen_at, last_seen_at,
                    state_checked_at, payload_sha, causal_id)
                   唯一键 = (source, object_key, state)
```

⚠ **`first_seen_at` 由我们写**，`payload_sha` 只当审计留痕——见 §9。

## 5. 边沿触发 vs 状态触发（这一节决定架构）

- **边沿（edge）**：`有推送`。发生一次、要抓住、过了就没了。webhook 天然合适。
- **状态（level）**：`开了个单且 N 分钟无人认领`。**webhook 给不出这个**——它只能告诉你「开单了」，
  不能告诉你「过了 20 分钟还没人领」。要判它必须自己存「我什么时候第一次见到它 / 现在有人领了吗」，然后**定时重评**。

> **边沿只是状态的一个瞬时切片。** 先问「它在我库里长什么样」，再问「能不能订阅它」。

站内已有 level 触发器的**完美模板 = `reapExpiredRuns`（reaper）**，它的理由就是同一句话 **【实测】**：

> 租约过期才是最常见的真崩溃形状（agentd 自己被杀 / OOM / 网络断 ⇒ **根本没有上报**），
> 所以不能靠上报，要定时扫状态 + 收敛 + **写一条用户可见的事件**。

`无人认领超 N 分钟` 就是这条循环换个谓词。**别新造机制。**

## 6. 规则只有四格

```
① 状态迁移   object_key 的 state 从 A 变成 B（或进入 B 且持续 N 分钟）
② 动作       注入一句话 / 起一个 run / 写档案 / 只发通知 / 只记一笔
③ 锚         落在哪个 cwd / 哪个会话 / 哪个 subject
④ 预算       per-rule 日限额 + 单 run maxRounds + 全局并发闸
```

**没有第五格。没有表达式，没有条件分支，没有循环，没有可视化编辑器。**

### 6.1 为什么必须拒绝表达式

规则一旦允许写谓词表达式，你就欠了它一个类型系统、一个调试器、一个「为什么没触发」的 trace——
而「为什么没触发」这一件，站内已经用多篇台账证明它是最贵的（#331 死光纤 / #371-A 库里存着读不出来 /
§8.87 读错观测面）。**这门语言的收益是「灵活」，成本是「不可解释」，而在自动化里不可解释等于不可用。**

### 6.2 作用域只做两层

- **全局**（管理员可开关）
- **会话/工作项级**（用户在这个工作项上开）

**项目级 / 工位级等真实需求出现再加。** 每多一层，「这条为什么没触发」的排查面就翻倍。

⚠ **「全局」不是分类学，是硬约束**：全局规则最终也必须落到**一个具体的 FDE + 一个具体的 cwd**，
否则没人跑它、没人付 token。这条把「作用域」从抽象层级变成了可执行的解析问题。

## 7. 血统与回环

### 7.1 内部回环（秒级，最危险）

```
规则起 run → run 终态 → 触发「终态规则」→ 再起 run → …
```

站内已有血统位 **【实测】**：`runs.trigger_kind` 的 CHECK 是
`('user_send', 'queued_steer', 'queued_follow_up', 'synthetic')`——其中 **`synthetic` 运行时零使用**
（本轮全仓 grep：只有这条迁移的 CHECK 里出现，`portal/src` / `runner/` / 前端零命中），
是迁移预留的血统位，一直空着。

**硬要求：`trigger_kind` 必须进谓词，不能只落库好看。** 否则「规则起的 run」会再次触发「终态规则」。

⚠ **一个建模警告**：**「谁发起」和「谁执行」是两个正交维度，不要塞进同一列。**
`trigger_kind` 说的是发起，员工说的是执行者——**一个 `user_send` 的 run 完全可以由某个员工执行**。
合成一列的后果：「员工干的、人发起的活」这类账永远分不出来，而它恰好是最想看的数。⇒ 需要独立的 `runs.actor`。

### 7.2 站外回环（分钟级，更阴险）

```
收工规则让 agent 提交并 push
   → 盯分支规则看到 push → 起 audit run
      → audit 也改了代码、又提交又 push
         → 盯分支规则又看到 push → …
```

周期是分钟级、**中间隔着外部系统**，因果上看不到任何连接，只会看到 agent 没完没了地自己跟自己说话、账单一直涨。

对策必须第一天就有：**谓词能排除「自己推的」**——
比对 committer 身份（`fde_git_accounts` 里有每个 FDE 的 git 账号），或要求 agent 的提交带一个 trailer
（如 `X-Station-Origin: rule:<name>`）。**后者更可靠**，因为它不依赖 git 配置正确。

### 7.3 深度上限

`causal_id` 链上算代次，超过 N 代直接掐并记一笔。**这是唯一能兜住「没想到的回环」的机制**——
因为你想不到的那些，正是会发生的那些。

## 8. 可见性不是锦上添花，是判据的一部分

**站内最高频的死法就是「静默不触发」，三种形态**：

| 形态 | 实例 |
|---|---|
| 库里存着，读不出来 | #371-A（写侧不过白名单，读侧白名单把它丢了） |
| 配了，没人读 | #331（`ERIX_SESSION_AUTO_TITLE` 下发但 runner 零读取 = 死光纤） |
| **判据落在错误的观测面上** | §8.87：我两次把「0 条 `compaction` 事件」当成「TTL 层没工作」，而 TTL 层**根本不发那个事件**；真相在 `compactionStats` 里（75 次触发、省 31.4 万 token） |

第三种最危险，因为它**看起来有数据**。那次错误的代价不是返工，是**差点建议撤掉一个正在省 31 万 token 的配置**。

⇒ **每个规则必须能回答四问**：上次何时被评估 / 谓词真了还是假了 / 命中后动作结果如何 / 花了多少。
**这四个答案不是 dashboard 的需求，是「这条规则存在」的前提。**

> **撤一个东西之前，先证明它在自己的落点上确实没工作。**
> **「引擎有这个层」≠「它在事件面可见」。每个事实都有自己的出口，猜出口就会得出反向结论。**

## 9. 幂等：键落在状态上，不落在载荷上

- **幂等键 = `(source, object_key, state)`**，**不是载荷哈希**。
- 语义源的输出**会抖**：同一个事实，两次搜索会给你不同措辞、不同证据条数、不同置信度。
  按载荷哈希判变化 ⇒ 每次都算新事件 ⇒ 那位名人被悼念一百次。

> **`state` 当幂等键，`payload/evidence` 只当审计留痕。**

⚠ **`object_key` 的粒度决定幂等语义**，选错就是漏发或重发：

| 想通知的事 | 错的 `object_key` | 后果 | 对的 |
|---|---|---|---|
| 会话完成 | `session:<id>` | 同会话第二次 run 完成 ⇒ 键相同 ⇒ **第二封信被吞** | `run:<id>` |
| 仓库有新提交 | `repo:owner/name` | 新旧 sha 状态相同 ⇒ 新提交不算新事件 | `repo@<sha>` |

⇒ 口径：**取「一次性的那个对象」，不是「持久的那个容器」。** 详见 [07](04-scenarios.md) §8.B。

- 站内现成件照抄：`client_event_id` + `ON CONFLICT DO NOTHING`（#277/#288/#292 那族），
  以及 `executeWithIdempotency` 那条被测试抓出来的教训：**台账里存的必须是响应体形状，不是业务结果**。

## 10. 背压与退避

**事件比执行快。** station 是 `capacity=1` 串行 + 每会话单活跃 run，而外部事件不会因为你忙就少来。

- **源侧退避**：没变化就拉长间隔。这是源的固有策略，不是配置。
- **总线侧背压**：队列深了就不拉（机械源）/ 不派探测（语义源）。
- **规则侧丢弃陈旧**：「这个 sha 已经落后 5 个了，别投了，只投最新的」——
  **事件的可变性决定它该不该丢**。
- **覆盖（supersede）**：新 push 来了而旧 audit 还在跑 ⇒ 正确动作**既不是取消也不是排队，是转向**。
  站内 `steer` 原语（`onRound` 里 abort，本轮跑完再停、把新信息接进上下文）正好是这件事 **【实测】**。

## 11. 明确不做

| 不做 | 理由 |
|---|---|
| **消息中间件 / 内存总线** | 站内总线已经是 DB（`run_events` / `queued_inputs` / 轮询表）。再引入一个 = 第二个真相源，违反「DB 是状态真相」，并把「重启后谁恢复」这个已解决的问题重新打开 |
| **可视化编排器 / 表达式 / DAG** | 见 §6.1 与 [01](01-decision-and-feasibility.md) §5：那是变成 n8n 的唯一路径 |
| **公网 webhook 入口（第一版）** | 现网用户面仍是明文 HTTP；投递入口是拓扑级的事，不是写个 handler 的事。先轮询 + 容器侧探测，零暴露 |
| **语义源（简化版）** | 语义源 = 一个 run = 需要 jail + 钱 + 账本，简化版三件都没有 ⇒ 而「能机械判的绝不允许调用模型」自动成立 |

## 12. 为什么重心是判决，不是消息流转

上一轮分析里我把「总线」当主体，那是错的。三条理由：

1. **总线是便宜的、可替换的。** 一张表 + 一个 tick + 几个适配器，谁都能写。它不是护城河。
2. **判决是昂贵的、不可替换的。** 站内为它付了八轮学费（见 §15、§16），那些学费换来的是
   「什么样的验收是假的」这一套判断力，而**这套判断力无法从任何框架里买到**。
3. **员工平台的瓶颈是验收带宽，不是员工数量。** 见 §17。

> **没有汇报线的 agent 是工具，有汇报线才是员工。**
> 工具自己说完成；员工被外部判完成。

## 13. 判决必须是封闭枚举

```
pass         判据全部通过，且证据可复核
red          判据有失败项（附失败项清单 + 坐标）
no-op-claim  执行者声称完成，但没有任何可复核的变化（最危险的一档）
needs-human  判据本身无法判定（需要人裁决）
```

**为什么必须封闭**（这是全套设计里第二重要的一格，第一是 [02](02-event-model-and-verdict.md) §2 的 `state`）：

- 一旦允许自由文本，你就无法聚合、无法告警、无法回答「上周有多少条是 `no-op-claim`」。
- 更重要的是：**自由文本的判决等于没有判决**。它把「谁来判」这个问题又推回给人，
  而人的带宽正是瓶颈（§17）。

⚠ **`no-op-claim` 必须单独一档，不能并进 `red`。** 它的语义是「它说它改了，但没有任何东西变」——
这是**最值钱的一档**，因为它是模型幻觉最典型的形态，而站内已经有一个血淋淋的标本：

> `requireDeliverable` 判的是「本次 run 用写工具**声明过**的每个路径都还在盘上」。
> 模型什么都不声明时**空集合恒真** ⇒ **一次工具都没调也能判 verified**（issue #391）。
>
> 而 `deliverablePaths` 判的是「**我要求**你交付的路径在不在盘上」——它不读模型说了什么，只读外部声明的清单。

## 14. 证据的形状

**一条判决必须携带能回到原始事实的坐标**，否则平台有权当它 `unknown`。允许的坐标形态：

| 形态 | 例 |
|---|---|
| 提交/引用 | `sha=3ae9129`、`refs/heads/main@abc123` |
| 位置 | `runner/lib/agents-md.js:223`、`docs/ops/x.md §17` |
| 执行 | `run id`、`exit code`、`not ok 7 - <用例名>` |
| 外部 | 完整 URL（含 commit/comment id，不是「那个页面」） |

三条**站内已经成文**的纪律，直接搬过来当证据规则：

1. **取证边界先行**：交付物第一格固定 `## 取证边界`，列出实际打开了哪些路径、哪些打不开；
   打不开就报 `BLOCKED: <路径>` 并停，**不许自行降级取证**。缺这一格 = 按未取证处理，结论不得采信。
2. **消费前抽验**：带 `file:line` 的结论，随机抽 3–5 条 `grep` 实跑对账再采信。
3. **二手不等于事实**：上下文摘要、旧笔记、别人的报告、issue 里的评论**都是自然语言改写过的二手事实**——
   改写会造出原物没有的东西。凡要基于这样一条前提做动作，**先在当前对象上现验一次**；验不过就当它不存在。

## 15. 判据的来源必须独立于执行者

这是「工具 vs 员工」的分界线，也是唯一不能妥协的一条：

| | 判据来源 | 能不能被模型操纵 |
|---|---|---|
| 工具 | 模型自己的声明 | **能**（空集合恒真） |
| 员工 | **外部声明的清单 + 可复核证据** | 不能 |

**推论**：判据必须是**声明式的、随工作项一起产生的**，而不是「执行者跑完之后自己写的总结」。
最省的形式是一份配置文件（`verdict.yaml` 之类），里面只写「要检查什么」，不写「怎么检查」。

## 16. 变异是判据的判据

一条判据本身也可能是假的——它可能永远绿。站内对此的答案不是「多加断言」，而是**变异**：

> **改一行它声称承重的代码，测试必须红。没红要么是覆盖真有缺口，要么是变异根本没改变行为。**

而这两者必须区分，站内为此踩过两次：

- **「变异没红」的两种成因**：覆盖缺口 / 变异是空操作（锚点没命中、写了同样的值）。⇒ 先证明变异真的改变了文件（`git diff --numstat` 非空），再谈红绿。
- **「变异红了」也要证明红来自你以为的那处改动**：有一次变异把文件改出语法错误 ⇒ `pass 0`，看着像红，
  其实是文件根本没跑起来。⇒ 红了要证明红在具名用例上。

⇒ **判决层的三条自检**（这三条在站内都是被事故逼出来的）：

1. 判据在**故意破坏**时必须变红（否则它是装饰）。
2. 破坏动作必须**先自证非空操作**。
3. 变红必须**点名到具体判据**，不是「整体失败」。

**这一层不能由模型来做。** 让模型跑变异、然后让它自己判「红了没」，等于让它给自己判卷。
变异必须是**机械执行 + 机械比对退出码**，模型只允许在「为什么红了」这一层发言。

## 17. 判据要随工作项存快照

**不能只留一个指向当前定义的引用。** 否则改了判据之后，历史 run 会变成「按今天的标准看它失败了」——
你在**重写历史**。站内同族事故：§8.40 那次把「待修缺陷」改判成「已钉住的哨兵」、
§8.86 那次「上游文档说删了 16 个导出、npm 上实际一个没删」——两次都是「同一件事的两个时点说法不同」。

⇒ 每个 run 落库时，把**当时生效的判据文本 + 版本**一起快照。

## 18. 两版必须完全一致的五件

如果这五件在简化版与加强版之间漂了，你就有了两个产品而不是一个产品的两档：

1. **判据的定义格式**（声明式，不是代码）
2. **判决的封闭枚举**（§13 那四个值）
3. **证据的形状**（§14 那四类坐标）
4. **源适配器的接口**（`cost` 是源契约字段）
5. **幂等键形状**（`(source, object_key, state)`）

**实现方式**：共享核心做成**零依赖纯函数 + 两份镜像逐字节对拍**。站内模板：
`terminationReasons.ts`（零 import、前端/vitest/node 三端共用）、`transcript-fold.js`
（portal 与 runner 两份，`SHARED-FOLD-CORE` 区间由测试逐字节钉住）。

> **加强版可以多，但不能改这五件。** 一改就是分家。

## 19. 语义源的三条铁律

语义源（agent 探测）是唯一一处「模型说了算」，所以它有三条硬约束：

1. **输出是封闭枚举，不是自由文本**（[02](02-event-model-and-verdict.md) §2）。
2. **状态迁移要「连续 K 次一致」**。机械源不需要确认（sha 不会骗你）；语义源需要——
   **至少两次独立观测都说是，才认定迁移**。写悼文这种事假阳性极贵（活人看到自己的讣告），值得多花一次探测的钱。
3. **不可逆动作必须要求证据可复核**（§14）。发出去就撤不回来的动作，不接受「我认为」。

### 19.1 正确用法：把模糊问题结晶成便宜的机械事实

> **语义探测应该是「一次性判定 + 落地成一个机械事实」那一步，而不是循环里常驻的传感器。**

「他去世了吗」搜一次、判定、写进 `celebrity_status.died_at`，之后**这个判断就退化成一个免费的机械源**
（查一列）。真正需要模型的只有「结晶」那一下。

⇒ 按正确用法，**每个对象一生用一次模型**。这也顺手回答了「agent 作为源会不会很贵」：
贵的是把它当常驻传感器用，不贵的是把它当一次性判定器用。

### 19.2 出口用现成的：notes

agent 之间的结构化信道不需要新造——站内 notes 已经建好并且验过：

- 有 key（幂等坐标，可排时间线的形态）
- 有 `write/read/list/complete/revoke/purge` 六方法，工厂在创建时 fail-closed 校验
- **已实测**「agent 写的注会经 semantic 段回到模型输入」（§8.67 E 片；顺带抓到探针不能取正文第二句、
  只能取小抄行——这是「一个 agent 的判断进另一个 agent 的输入」这条链的实测边界）

⚠ **一个必须一起解的空缺**：notes 作用域是 `sessionId`，而「名人 / issue / 分支」这些对象**跨会话**。
⇒ 「跨会话的机器档案放哪」不是可以以后再说的细节，**它是 agent-as-source 的硬前置**。

⚠ **出口是「写一个结构」，不是「说一句人话」。** 判定要读它落的东西，**不要解析它的终稿文本**。
（站内同族纪律：收尾产物一律直接写文件，不许用 glob 猜名字。）

## 20. 验收带宽：加员工的边际收益在你自己身上归零

技术事实是 `capacity=1` 串行 + 每会话单活跃 run。组织学事实是同一件事：

> **如果每个员工的产出都要人验收，那么 8 个员工 = 你从「干活的人」变成「8 个员工的经理」，
> 而经理是串行的。**

⇒ **加员工的边际收益，在你自己的验收带宽处归零。**

这不是可延后的细节，它决定整套平台成立与否——因为**「验收」是六件套里唯一不能靠加机器扩容的一格**。

所以 [02](02-event-model-and-verdict.md) 与本文那些看起来「锦上添花」的东西，其实是地基：

| 机制 | 它真正的作用 |
|---|---|
| `deliverablePaths`（外部声明清单） | 把验收从「读一遍」降成「跑一条判据」 |
| 变异探针 | 让「看起来没问题」这种结论拿不到钱 |
| 判决封闭枚举 | 让人只需要处理 `needs-human` 那一档 |
| 证据可复核 | 让人抽验而不是全验 |

**这四件合起来是同一个动作：把人的位置往上移一层。** 不做这个，员工越多越慢。
