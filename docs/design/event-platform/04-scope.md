# 04 · Scope：简化版 / 加强版各包含什么

> 状态：可研（2026-11-07）。
> 分裂轴 = **事件源与作用对象的边界**（系统内 / 系统外），不是「功能多少」。
> 本文件只划边界，不排期、不定 DDL。

---

## 1. 两版逐层对表

| 层 | **简化版**（内部事件 → 内部资源） | **威力加强版** |
|---|---|---|
| **判决层**（[03](03-verdict.md)） | ✅ **全部**（这就是它存在的理由） | ✅ 同一份实现 |
| 证据形状 / 封闭枚举 | ✅ 全部 | ✅ 同一份 |
| 源适配器 | ✅ 3~5 个**机械源**（git 灯、测试退出码、文件存在、账本事实） | ✅ 全量（机械 + 语义 + 人类） |
| **语义源** | ❌ **不做** | ✅ |
| 工作项（`subject`） | ❌ 用现成的锚（会话 / 目录 / 分支），不建新表 | ✅ 自己的账本 |
| 角色 / 员工定义 | ❌ 一个规则就是一个角色，写死在配置里 | ✅ 可实例化 |
| 工具面裁剪 | ❌ 不拥有工具 | ✅ |
| 多租户牢笼（L0） | ❌ 用 station 现成的 | ✅ |
| 身份 / 钱 / 入口 | ❌ 用 station 现成的 | ✅ |
| 账本（transcript / 折叠 / 终止） | ❌ 用 station 现成的（L1） | ✅ |
| dashboard | ❌ | ✅ |
| DB | ❌（最多一份本地 JSON / 复用 station 库） | ✅ |

**关键一格：简化版没有语义源。** 这不是砍功能，是硬约束——
语义源 = 一个 run = 一次模型调用 = 需要 jail、需要钱、需要账本。三件都没有的时候，
**「能机械判的绝不允许调用模型」这条原则自动成立**，而这恰好是简化版最该有的纪律。

## 2. 简化版的事件面：四个，三个已有

**判据（[09](09-catalog.md) §1.1）：有没有一个人，在不知道这件事的情况下会做错决定。**
按它过一遍，初版的十个源只剩四个——其余六个分别是「平台自己的故障」（内置告警）
和「统计/运维小事」（一条 cron 或一个管理台页面就够）。

| # | 事件 | 出处 | 今天的状态 | 不知道会做错什么 |
|---|---|---|---|---|
| E1 | run 终态（10 种 reason） | `runs.termination` | **已有**，只上了颜色 | 以为还在跑 / 以为成了 |
| E2 | 收工灯（7 个 reason） | `gitlight.js` + `GET /api/git-light` | **已有**，**只上色，没有执行者** | 以为收工了，其实没提交 |
| E3 | 端口对账（分配 vs 实际在听） | `port_allocations` × `port_observations` | **已有两张表**，差集没人算 | 以为预览能用，实际打不开 |
| E4 | 时钟 | —— | **需新建**（很小） | 以为检查过了 |

> 结论修正：**「十个源零新建」是虚的。** 那个数字之所以好看，是因为它把平台的 bug（砖化/租约/镜像漂移）
> 和统计数字（预览 415/413 分布）都算成了「事件源」。**从「系统里有什么」出发列表，一定会这样。**

### 2.1 不进事件表的三类

| 类 | 项 | 去处 |
|---|---|---|
| **平台自己的故障** | 账本形状、队列卡 `delivering`、租约/停滞/重排耗尽、镜像漂移 | **内置告警**（不可配置、不可关闭）+ 运维手册 |
| **不需要框架** | 证书到期（平台的门锁，坏了影响运维不影响用户）、预览缺件统计（产品该支持什么格式） | 一条 cron 邮件 / 管理台已有页面 |
| **现在不做** | 上游发版（一次性仪式 + 需要语义源）、应用不健康（当前全是 dev 环境，会变误报机） | 延后 |

## 3. 简化版的资源面：全部已存在

| 动作 | 出处 | 关键性质 |
|---|---|---|
| 往会话投一句话 / 起 run | `postMessage` + `drainQueuedInputs` | CAS 认领 `pending→delivering` + **过期重认领** + 容器存活闸门 + 阻塞原因 |
| 转向 / 停止 | `steer_arm` + `onRound` abort | 本轮跑完再停；不新增 run 状态 |
| 写 note | notes 六方法 | **已实测「agent 写的注回到模型输入」** |
| 起 / 停 / 重建容器 | `provisioner.js` | 已有 409 幂等、adopt 分支 |
| 写文件（jail 内） | 文件工具（5 个） | 边界谓词「相与」不是替换 |
| 改路由 / 换证书 | `routes.js` / `tls-cert.js` | 已带审计、已带回滚 |
| 只发通知 | mail（#457）+ 审计日志 | channel 已存在 |

⚠ **一条必须避开的坑**（读代码读出来的）**：定时/规则触发不能直接复用 `follow_up` 的投递判定。**
`drainQueuedInputs` 的判定表写着「`failed` / `persistence_failed` / `max_rounds_cap` ⇒ **不投，留在队列**」
（别把排队的话烧在一个坏 run 上——这是对的）。但规则继承这条就会得到：
**一次失败 ⇒ 后续所有唤醒堆在队列里出不来**，而人不在跟前，你永远不会知道日报从周二起就没发过。
⇒ 规则触发要么走独立的 kind 并自带「不投也要记账 + 过期作废」，要么根本不入队、直接 `postMessage`。

## 4. 简化版真正要新写的只有四小格

| # | 要写什么 | 为什么绕不开 |
|---|---|---|
| 1 | **规则表**（四格 + 作用域 + 预算） | 没有它就没有平台，只有一堆散落的 cron |
| 2 | **谓词求值 + 边沿/状态区分** | 照 `reapExpiredRuns` 的三条分支抄，别新造 |
| 3 | **血统**（`trigger_kind` 进谓词 + 深度上限） | 没有它就是秒级无限循环（[02](02-model.md) §7） |
| 4 | **可见性面**（上次评估 / 真假 / 动作结果 / 花费） | 没有它就分不清「没触发」和「不该触发」（[02](02-model.md) §8） |

**其余全部复用。** 这四格里，第 3、4 格是「不做就会死」，不是「以后补」。

## 5. 加强版多出来的

| 多出来 | 为什么简化版没有 |
|---|---|
| **外部源**（Gitea API / `ls-remote` / npm `dist-tags` / webhook） | 要凭据 + 要出网 + 要验签 + 要幂等 |
| **语义源**（agent 探测） | 要 jail + 钱 + 账本 |
| **工作项账本**（`subject` 进模型） | 简化版用现成的锚就够 |
| **角色 / 员工定义 + 工具面裁剪** | 简化版一个规则就是一个角色 |
| **多租户** | 简化版就我们自己一个实例 |
| **dashboard** | 简化版靠日志 + 一次 SQL |

⚠ **`subject`（工作项锚）是加强版里唯一要动会话模型的一格，也是最值的一格**：
它把「外部对象 ↔ 谁在干 ↔ 花了多少」变成一等公民。

⚠ **它的债要一起认**：一个活跃仓库一天十几次 push 灌进同一个 `subject`，就是**长会话砖化的另一个入口**。
站内修过六轮账本形状缺陷（分页切轮 → 链式 `partOf` → 未结清 `tool_use` → `:resume` 裸重放 →
归档线性膨胀 → 取错折叠行），**别主动往里灌**。所以锚必须配去抖与合并。

## 6. 简化版砍掉的是外部的麻烦，不是系统的麻烦

这一点必须写在 scope 里，否则会有人以为「简化 = 简单」：

| 麻烦 | 简化版砍掉了吗 |
|---|---|
| 外部凭据 / 出网 / 验签 | ✅ 砍掉了 |
| 语义源的抖动与幻觉 | ✅ 砍掉了（不做语义源） |
| **回环** | ❌ **更危险**（周期秒级、同一张表、因果不可见） |
| **静默不触发** | ❌ 一个没少，而且内部事件面更密 ⇒ 更容易选错观测面 |
| **事件快于执行** | ❌ 一个没少（十个会话同时终态就会堆） |
| **成本失控** | ❌ 反而更容易（外部客户会催，内部事件不会） |
| **「有用」无法自证** | ❌ 只能靠「被赎出多少小时」 |

⇒ 五个硬问题的分析在 [05-feasibility.md](05-feasibility.md) §3。**它们就是可研的正题。**
